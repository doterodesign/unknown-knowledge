# Cedar group — additional synthetic, independently owned artifacts

Draft development-v2, captured 2026-09-18. North, South and Holding remain three
independent installations. No import, federation or combined identity is active.
This source package describes the separate owners; it does not consolidate them.

## north-knowledge

In cedar-north, Knowledge K-000001 is a reviewed note on winter freight crates:
use a weather cover. It is not Ontology O-000001, which names the local asset-
export contract. Equality of a numerical suffix across kinds is not identity.

## nord-glossary

The accepted cedar-north glossary uses “Nord” as its French-language short name
for the North subsidiary. This alias establishes a name within that context;
it does not authorize resolving unqualified North identifiers in South's store.

## south-nord-project

In cedar-south, Nord is the name of a proposed logistics software project. Its
draft lists CSV as a hoped-for output. It has not been approved or deployed and
is unrelated to North's active PNG/SVG asset exporter.

## repeated-branches

North labels a local technical branch “software / export.” South independently
uses the same branch wording for document transport. Neither owner declares a
parent relation, equivalent subject or import edge to the other's branch.
Their identical labels are insufficient to create a group-wide descendant set.

## retired-north-tiff

North's retired Ontology O-000002 describes an earlier TIFF-only asset exporter.
It was withdrawn before the current O-000001 PNG/SVG contract became active.
The historical TIFF behavior is not a current supported-format promise.

## proposed-correspondence

A proposed holding-company planning note says a future importer could review
North's O-000001 as an asset-format concept and South's O-000001 as a document-
transport concept. It explicitly calls for distinct destination identities.
No destination IDs have been allocated, no import approved, and no correspondence
is operational. The note describes a proposal, not an executable mapping.

## unlocated-package

A reviewed archival manifest says a component supports EPS. Its installation,
owner and release are unknown. Review verified the transcription, not ownership
or current applicability. It cannot establish EPS support for North or South.

## rejected-union

An accepted holding-company review rejects a blanket rule that combines local
export formats whenever local IDs or subject labels match. Reading permitted
sources from two owners can support separately qualified statements; it still
does not create a single governed record or shared authority.

## trade-port

Port Elm. It describes no software format, local concept identity or federation.
