# Finite migration publication with retained operational history

This guide describes the retained finite migration profile. The separately
identified [installation cutover profile](ucs-1240-installation-cutover.md) adds
exact installed assets, reviewed whole-repository consumer roles, operational
suppression/rule handling and bounded observed local activation. Its explicit
inputs and review requirements do not broaden the finite profile described here.

The `identity-migration-publication-v4` descriptor binds the fixed historical
08066b5 profile, the finite representative recipe, five required surfaces
(query, paths, documents, generated views, retained operational history), and Markdown/text adapters. This is
one admitted pre-Subject source profile, not completion of arbitrary migration.
Nonempty rules, unknown operational source roles, other required adapters and
identity-only tie reordering remain unsupported. Canonical lookup is unchanged;
the historical distribution is isolated offline comparison code.
Finding/gap/miss documents now receive explicit actual historical/current
`validateStoreFile` calls; loader health alone does not cover those roles. In both
root and nested-kit layouts, actual CLI checks receive the snapshot repository
root; in-process loaders receive its verified kit root. Knowledge file replay
paths include the actual kit prefix.

`runFinalPreparedMigrationGate` takes retained validation coordinates, an
independently approved complete runtime profile, explicit evidence/runtime
limits, and private `migration: {migrationInputs, limits, semantic}`. Semantic
input is `{today, requiredAdapters: ['md@1', 'txt@1'], limits: {maxCases,
maxInventoryBytes, maxGeneratedBytes}}`. The private migration choices are
resupplied on every final/review/publication call. Their actual fresh mechanical
gate digest must equal the retained digest. The mechanical v1 preimage and DTO
are unchanged; v4 is the final publication policy. Earlier v2/v3 scope remains
historical evidence; its runtime/policy cannot authorize current publication.

The fixed final worker executes both actual engines. Historical health,
structural and values checks are mandatory; resolver exit 0 is insufficient.
The complete admitted vocabulary and path recipe is reserved before execution.
Actual no-hit controls must have no matches. Required records and declared
relations must be observed. The v2 recipe has up to two nonempty vocabulary passages and one unmatched
passage. Markdown has one native section per retained passage; txt@1 has one
native whole-document section, as its actual adapter specifies. With no K/O
vocabulary, both are real unmatched-only controls. No text boundaries
are fabricated, and both complete native coverage outputs are retained.

The private comparator validates closed retrieval shapes and translates only
typed identity positions. Mixed resolved-context arrays must match their exact
operation/concept/jurisdiction segments independently. Concept signals must name
actual declared concepts. All other fields and every array order must agree.
Call numbers are corroborated with each actual owner synthesis. Actual
deriveArtifacts, buildIndex, buildTree/projectLeaf and renderTree results are
corroborated on each side; the index and both complete ordered trees are compared.
Both renderers also process the same original tree: only the frozen L-to-K
citation instruction differs. Raw original outputs remain separate; no paired
IDs, rebased DTO or correspondence is retained.

Case and inventory capacities reject shortfall without pruning. Generated
capacity bounds admission/retention of all raw artifacts plus typed index/tree
wire bytes across both sides. Native owner generation and JSON serialization
allocate before exact output-size measurement; this is not a hard heap bound.
The existing combined child-output limit, per-check deadline and whole-worker
process-group deadline remain in force. No timeout or capacity is auto-expanded.

The final result is `{version, kind:'final-prepared-migration', policy, source,
candidate, runtimeDigest, capability, gate, status, diagnostics}`. `gate` is the
actual closed version-3 semantic report, including the unchanged actual mechanical gate,
runtime/profile bindings, actual optional-store presence/counts, full recipe, validation outputs, separate per-side
replays, operational history and generated outputs. Review operationEvidence adds
`finalGate: {resultDigest, result}` to its mechanical capture bindings. The
writer and publisher accept the private migration envelope separately from the
request. Actual candidate namespace must equal the reviewed namespace. The
three retained review files are unchanged. Unexpected child output is a static
refusal; the private job is deleted before output admission and on cleanup.

Old v1 mechanical-only reviews retain their review-only role and always refuse
publication. The sole publisher requires fresh v4 evidence before its final
atomic ref CAS. No merge, activation or push is performed. Tests use disposable
repositories and explicitly synthetic trusted profile/operator responses.


The explicit `migration-operational-history-v1` policy admits Phoenix, finding,
gap and miss roles from the fixed historical source versions. The source-span
owner is reused to verify complete candidate bytes, including exact reviewed
prose edits in operational fields such as mixed `resolved-context`. No independent
ID replacer or arbitrary text normalization is introduced. Both actual role
validators must pass; typed references must resolve through the private actual
record correspondence. Separate original parsed documents, raw hashes/sizes,
candidate Git capture locators and validator results are retained. Private
expected bytes, review explanations and mapped objects are not retained.

Both actual Phoenix edition-accounting owners must pass. Every leaf's edition
and ordered retained move-event list are compared using file order and private
typed identities; carried-forward rows do not increment edition. Event identity,
row order, reasons, dates, counts, scope and all bytes outside approved identity
and schema spans remain protected by complete candidate equality. No Phoenix
event is applied during migration. Operational evidence and the complete recipe
share `maxInventoryBytes`; retention measurement follows native allocation and
does not constitute a heap bound.

This finite addition addresses r3 §9 operational-history requirements. It does
not complete installation-wide activated-consumer inventory, other source
grammar variants, nonempty rule grammars, arbitrary extensions or HTML/PDF replay.
Required formats depend on activated readers, validators and writers. r3's
stable-order requirement does not permit sorting away cross-version differences.


[Optional-store source profiles](ucs-1240-migration-source-profiles.md) now admit
actual healthy missing stores, including Decisions-only, with equal presence and
authored payload counts on both sides and at least one actual payload overall.
Absent, empty-present and malformed/non-directory stores remain distinct. The
ordinary resolver does not search Decisions; that coverage is mechanical/record
validation. Empty Knowledge views remain detached in-memory proof, never new
candidate files. The source profile joins the recipe/history inventory budget;
zero leaves do not waive generated byte capacity. The original recipe-v1 export
remains unchanged while the final policy selects explicit recipe-v2.
