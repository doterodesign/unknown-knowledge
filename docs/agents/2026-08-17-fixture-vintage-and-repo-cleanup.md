# Fixture vintage and repo cleanup

Two-phase change on the `unknown-knowledge` kit. Phase 1 removed throwaway
prototype/planning artifacts; Phase 2 re-cast the entire fixture and example
world as a client-neutral product-design studio. This record describes the new
state and the deletions.

## Phase 1 — prototype/planning artifact removal (merged, PR #70)

Deleted from the repo root, none of which were part of the init payload (D-007)
or wired to the engine:

- `PRD.html`, `ORCHESTRATION.md` (tracked)
- `architecture.html`, `library-walkthrough.html`,
  `search-experience-prototype.html`, `faceted-store-prototype.html` (untracked
  working-tree leftovers)
- stale `.claude/worktrees/` leftovers

Every repo reference to a deleted file was updated or removed (README,
CONTRIBUTING, a scaffold-layout test, an init-copy traversal-attack fixture, two
engine-lib provenance comments, one fixture decision-entry header comment). The
historical records under `decisions/`, `docs/agents/`, and `logs/` kept their
original citations except where Phase 2's confidentiality sweep required
rewording them anyway.

Gates green (npm test / lint / acceptance); CodeRabbit review addressed (two
minor findings fixed); squash-merged to main.

### Semantic roles preserved

- **The five UCS-1159 plants** keep their exact codes and detection paths:
  stale-volatile leaf (`preflight --today`, exit 1), jurisdiction mismatch and
  unregistered facet (both `unregistered-value`, distinguished by path),
  duplicate-id and unresolved-ref (loader hard errors, exit 2, in isolated
  stores). The jurisdiction plant is now an accessibility-law region (`eu-eaa`)
  with an empty registry; the stale plant is a volatile release-deprecation
  leaf.
- **The phoenix split** keeps its "one class splits into two, one leaf goes the
  other way because it was misfiled" story: L-000117/L-000213 → primitives,
  L-000133 (empty-state pattern guidance, shipped alongside a component but
  really a pattern) → patterns. Editions, accession ids, decision id D-420, and
  the per-row `why` prose all preserved; the `split-after/` golden is
  byte-identical to a real `phoenix.js --apply` run.
- **Call numbers are derived, not hand-edited.** The derived-layer trees and
  call numbers were regenerated by running the engine against the rewritten
  stores; the golden tree in `tests/derived-layer.test.js` is the engine's real
  output for the new domain segments (`DES/COM/…`, `ENG/FRO/…`, `BRA/IDE/…`).
- **Accession, decision, and concept ids unchanged** wherever they were before
  (L-NNNNNN, D-NNN, K-NNN); only slugs, titles, domains, bodies, and vocabulary
  values changed.
- **Registry↔store consistency** was swept explicitly per store: no leaf carries
  a value the registry does not mint, and every minted value has a leaf carrying
  it — except the deliberately kept fixed-vocabulary and lifecycle values (the
  three truth anchors, the pre-promotion stages) that are minted by the store
  model rather than by any one leaf, exactly as the acceptance fixtures document
  them. This is the recurring defect class (a registry contradicting its own
  store), and it was checked in both directions.

### Preservation notes

- No fixture's semantic role had to be sacrificed. The one place worth flagging:
  the resolver-v2 jurisdiction values are now hyphenated two-segment identifiers
  (`us-ca`, `eu-eaa`) rather than the previous single-word place, so an ask that
  names one ("us ca") opens into two tokens. The query-decomposition goldens
  were updated to the two-token `matched`/`tokens` shape accordingly; the
  exclusion, near-miss, and residue semantics are unchanged.
- The near-miss golden needed a query where the operation overlaps on exactly
  one of its two words; "theme lifecycle" plays the role the old single-overlap
  query did (matches K-103 by alias, near-misses `export-theme` on "theme").

### One retained billing surface (judgment call)

The Swift fixture keeps `Sources/Payments/Providers.swift` (in-app billing
providers, e.g. Stripe/Adyen) as its computed-array "unextractable" miss
specimen. In-app billing is a client-neutral surface any SaaS design tool's
mobile app carries, and the file holds no sports-betting or gambling
vocabulary. The shipped skill-doc example that referenced this path was
changed to a neutral `Sources/Integrations/Providers.swift` so the payload
carries no fixture-specific path.

### Structural filenames kept

A few fixture paths are topic-neutral structural names and were left as-is to
avoid churn: `src/feed/latency.ts` and `ontology/classes/100-feed.yaml` in the
derived cluster carry no old-topic vocabulary and read as ordinary engine
scaffolding.

### Confidentiality sweep

A case-insensitive, word-boundary sweep of the whole tree for the old topic's
vocabulary family returns zero matches (excluding the substring false positive
"sport" inside "transport"). A fresh `init` into a temp dir was swept the same
way — the seeded payload tree is clean, which matters most because payload ships
to client repos.
