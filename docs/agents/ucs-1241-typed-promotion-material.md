# Retained material in typed K/O/D promotion

This implements step 3 of the [lifecycle continuation contract](lifecycle-material-continuation.md)
and the [reconsideration Decision](../../decisions/entries/suppressed-subject-reconsideration.yaml).
The fixed homogeneous Knowledge, Ontology and Decisions promotion owners retain
their existing allocation, source transformation, genesis, preflight and impact
policies. This increment does not add new worker names or publication policy IDs.
Verification receipts below are scoped implementation evidence, not publication
of the proposed Decision or approval of customer records.

## Original input and owned evidence

An own `evidence.materialCaptures` selects continuation, including explicit `[]`.
Omission retains native typed report version 2 and its previous input/counters;
continuation uses outer report version 3. Wire version 1 and the existing
`typed-record-promotion-v3` impact policy remain unchanged. Null, undefined,
accessors, sparse arrays and duplicate evidence refuse at the new admission.

[record-promotion-input.js](../../payload/engine/lib/record-promotion-input.js)
obtains the exact own-data governance capacities, creates one authentic allowance,
guards metadata, then reserves/copies each raw occurrence or decodes each wire
occurrence once through the existing capture mechanics. The owned evidence has
Decision, assessment and material families. Existing canonical-base64 grammar
and byte-integrity rules are reused. Reusing those same owned objects in later
checks does not charge a second copy; additional actual captures are charged.
Failed reservations are usage evidence, not proof that a copy completed.

The fixed prepared/final workers enter `runPreparedRecordPromotionGateFromWire`.
They do not decode into a raw owner that admits the buffers again. Parent/final
retained processing preserves the original wire; its predicate binds the report
version, digest, limits and successful resource shape to that wire. It does not
independently evaluate Subject queries or treat a report as authority.

## Actual source and genesis proof

The typed owner reuses its existing actual snapshot models, native allocation
planner and exact candidate transformation. The same owned evidence and allowance
reach both actual governance evaluations, supplied-source verification and new
assignment checks. Native allocation is not repeated to make expected test data.

The fixed source verifier checks all supplied declarations after actual capability
and registry preservation checks. Sourced captures retain full Git provenance;
source-less material may match either actual side, and mixed assessment pairs
require a common side. No omitted unrelated declaration is fetched. These checks
establish file provenance, not material novelty, selected-record content truth
or world truth. Existing current-authorizer and whole-file preservation checks
remain mandatory.

With actual Subject authority, revision-zero genesis rows use the existing
`validateContinuedAssignmentChange` and the actual candidate handle bound to the
same allowance. Without a registry, the native unknown/empty assignment behavior
remains available. No handle is fabricated. Nonempty material refuses without
actual Subject authority; nonempty assignments still fail native eligibility.

Every continued genesis row charges `record-promotion-genesis-row` and guards its
actual qualified reference, raw record and file metadata before native row work.
The entire parser entry is not a JSON document: Knowledge entries may contain
undefined bookkeeping fields. The projection bounds the substantive record data
without repairing or replacing the actual entry supplied to native validation.
Expected new continuation errors are adapted to failed reports. Earlier completed
rows and accumulated usage remain visible on later budget refusal.

Registry correspondence charges both committed bytes and the actual materialized
reread for the new profile. A direct actual-Git test exposed a missing second
5,764-byte charge; the corrected path accounts for 11,528 bytes. Omitted typed
behavior is unchanged. Promotion source-read limits and assignment capture limits
remain distinct native reports. Independent impact reload/evaluation, native Git
and parser work retain their existing exclusions. This is not an end-to-end CPU,
I/O or report-byte bound.

## Retained continuation and limits

Existing prepared validation, fresh final execution, runtime capability checks,
review receipt binding and atomic source/output ref transactions are reused.
Final review/publication rereads actual evidence and requires exact fresh owner
proof. Loss of a declared historical source cannot be excused by intact retained
report bytes. The prepared predicate alone grants no release or runtime authority.

The owner fixture hand-authors the three initial assignment states and fresh
canonical IDs after a real successful reconsideration. Optional-registry controls
reuse the existing actual typed fixture; they truthfully have no reconsideration
handle or historical material. A separate source-helper test uses actual changed
proposal bytes to prove source-less correspondence with the before side only.
That helper-level control is not a full retained model-declaration test. The full
retained matrix uses actual historical source material; no claim is made that
every source profile has independent end-to-end coverage.
