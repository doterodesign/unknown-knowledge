## Review round (CodeRabbit, 2 findings)

**MAJOR — inherited prototype keys accepted as volatility classes. Fixed in `8d102f3`.**
`VOLATILITY_LIMITS` was an object literal and membership used `in`, so `volatility: toString` read as a known class whose limit was a native function. Reproduced through the resolver CLI: a leaf verified 366 days earlier came back `verdict: trusted`, `downranked: false`, with `limit` **absent** from the JSON (`JSON.stringify` drops function values) and `[native code]` in the reason string. The schema enum rejects the value, but the resolver never gates on store health (§4), so it is exactly the surface that can publish a verdict on a leaf no check approved.

Fixed at two levels: the table is null-prototype so the bug class is gone at the source, and `leafVolatility` uses `hasOwnProperty.call` so the gate is correct independent of how the table is built. `validate.js` now reads through `leafVolatility` rather than spelling its own `in` test — a second spelling would have demanded a `verified` date from a class with no threshold. Three regression tests added, including a JSON-round-trip assertion (which is what catches the dropped-key harm).

**MINOR — explicit `applies: { jurisdictions: [] }` on fixture leaves. Declined; underlying defect fixed.**
Absence and explicit `[]` are indistinguishable to the engine (verified: both clean, neither checked — membership judges list values and there is no list). Adding it would encode a Space claim into fixtures that isolate Time. But both `jurisdictions.yaml` headers were copied from UCS-1149 and falsely claimed "Both leaves here claim universally (`applies.jurisdictions: []`)" when none of the seven leaves declare `applies`. Both headers rewritten; the other five copied headers audited and correct as inherited.

## What shipped

Every leaf may carry a `verified` date and a `volatility` class. The engine turns those into a pinned freshness verdict computed by **one** shared function, so the surfaces that demote on it cannot disagree. A stale leaf is demoted deterministically in every projection, with its reason in the output, and is never hidden.

## Design decisions

| Question | Decision | Why |
|---|---|---|
| Field placement | Top-level, not under `facets` | Matches the spec prototype. `facets` is registry-governed classification of what a leaf *is*; time is a governance fact about the record's upkeep. |
| Volatility vocabulary | Schema enum, **not** a registry | Unlike `form`/`anchor`/`stage`, whose values the engine only compares, each volatility value is a key into a pinned numeric table. A registry-minted fourth class would yield leaves with no threshold — a governed field silently ungoverned. |
| Absent volatility | Exempt from time governance | The facet is v2 and stores are mid-migration; defaulting would stale every un-migrated leaf at once. `exempt` is its own class, deliberately not `trusted`. |
| Preflight mapping | `stale` is its own verdict class | The ticket says "trusted/stale". Nothing about a stale leaf is broken (≠ quarantined) and its checks ran and answered (≠ unknown). |
| Stale exit code | 1, not 2 | The contract reserves 2 for a check that never ran. The time check ran; rotted knowledge is a finding to fix. |
| Shared module | `lib/time-verdicts.js` | Three surfaces demote on it today; UCS-1158/1152 inherit. A test asserts no surface spells a threshold in code. |

## Details worth remembering

- **`JSON.stringify(Infinity)` is `null`, silently.** Static's published `limit` is an explicit `null` with `volatility` carrying the distinction — otherwise "never stales" and "no limit applies" are the same bytes. The *comparison* still reads `VOLATILITY_LIMITS` directly.
- **Static short-circuits before both the date check and the `--today` check.** Neither can change its answer, so reporting it `skipped` would tell a reader to pass a flag that cannot help them, and `undated` would demote a leaf whose declared property is that it cannot rot.
- **Preflight asks stage before time.** A leaf no moderator promoted is unverified for a reason that outranks its age; re-dating a draft would not make it trusted. The resolver reports *both* demotions because it ranks rather than verdicts.
- **The validator is deliberately date-free.** It asks whether a leaf *can* be judged, never whether it is stale, so the baseline finding set is identical on every run (D-012).
- `tests/frontmatter-v2.test.js` previously asserted `verified`/`volatility` absent as "a later ticket"; that fixture is untouched and still passes, because the time-facet fixtures are new stores rather than mutations of pinned ones.

## Not done (out of scope, by ticket)

Derived-layer trees (UCS-1158) do not exist yet, so "every generated projection" today means resolver query output, resolver `--paths` output, and preflight leaf verdicts. All three are covered; the derived layer inherits the same verdict function when it lands.
