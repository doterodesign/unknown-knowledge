# Prepared migration gate — mechanical evidence

This guide describes the retained finite migration profile. The separately
identified [installation cutover profile](ucs-1240-installation-cutover.md) adds
exact installed assets, reviewed whole-repository consumer roles, operational
suppression/rule handling and bounded observed local activation. Its explicit
inputs and review requirements do not broaden the finite profile described here.

`payload/engine/lib/prepared-migration-gate.js` exports
`runPreparedMigrationGate`. It checks actual committed source/candidate bytes;
it never writes Git objects/refs or approves adoption. Impact remains
not-performed and publicationReady is always false.

## Closed input

```js
{
  repoRoot,
  source: {commit, tree, kitPath},
  candidate: {commit, tree, kitPath},
  migrationInputs: {
    namespace, publication: {id, review},
    proposals, declarations, adjudications, proseDecisions
  },
  limits: {
    maxTreeEntries, maxTreeBytes, maxFileBytes, maxGitOutputBytes,
    maxSourceDocuments, maxRecords, maxReferences,
    maxAdjudications, maxProseEdits, maxInputBytes
  }
}
```

Every array is explicit, including empty arrays. Nested entries use the existing
rewrite contracts. Declared-only pending-import occurrences each require
`{source, disposition:'allocate'}`; they never invent payload or lifecycle.
Proposal-only declarations and ordinary missing-file targets remain unsupported.
Current target schema versions are fixed internally. No caller model, callback,
runtime path, changed-path proof or required-check list is accepted.

Limits are positive safe integers. maxFileBytes fits both maxGitOutputBytes
and the shared 64 MiB reader cap. Complete raw tree listings and blob sizes are
bounded before materialization; combined listing bytes also fit the smaller
reader/output cap. Data parsing remains bounded by tree/file bytes; document,
record and reference counters refuse inventory above their logical limits.
maxAdjudications bounds the combined proposal, declaration, reference and prose
choice count. maxProseEdits bounds all prose edits. maxInputBytes bounds the
serialized migrationInputs. The private input copy precedes asynchronous work.

## Actual checks

The gate uses P1 readCommittedTree/withTreeSnapshot/changedTreePaths. Both
commits must corroborate their own claimed trees and selected kit paths; the
candidate must have exactly the source parent in its raw commit headers; Git
grafts or shallow revision-walk state cannot provide that proof. Source and candidate retain the
same kit layout in this slice. It independently inventories the committed
source, recaptures its exact raw files, reruns the actual migration rewrite,
and compares the complete candidate tree and mode set with that expected result.

The new `_identity.yaml` has one fixed encoding in this slice: UTF-8 bytes of
`JSON.stringify(rewritten.identity)`, no trailing LF, mode100644. JSON is valid
YAML. Exact generated bytes prevent unrelated comments or an authored identity
crosswalk from being attached to an otherwise semantically equal new ledger.
Existing rewritten documents preserve all bytes outside authorized spans.
Other files and modes are unchanged. P1's actual canonical loader/index and
full structural/value functions inspect the candidate. An unclassified source
path fails source scope; supplied-document success does not imply full coverage.

No canonical before model or compatibility lookup is fabricated. Missing
capability/compatible-source replay evidence is not performed; this gate does
not implement the final migration impact policy.

## Closed retained report

```js
{
  version: 1, operation: 'identity-migration',
  source, candidate, objectFormat, validationInputDigest,
  mechanicalStatus: 'passed' | 'failed',
  checks: [{id, status, code, counts}],
  scope: null | {
    coverage: 'committed-installation', sourceFiles, unclassifiedPaths,
    records, declaredOnly, references
  },
  resources: {
    limits, sourceTree: null | {entries, bytes},
    candidateTree: null | {entries, bytes}
  },
  impact: {status:'not-performed', code:'migration-impact-unavailable'},
  publicationReady: false
}
```

Malformed inputs return null source/candidate/objectFormat/input digest and
resources.limits; arbitrary caller values are not echoed. Valid copied snapshot
descriptors are retained, but their actual corroboration is the committed-pair
check, not their presence in the report. objectFormat is null until established.
Every check has status passed/failed/not-performed and code null or a static
engine-owned failure code. Unexpected bugs still throw; a migration runner must
not retain crash/malformed/stderr output as known safe evidence.

Check order and evaluated count shapes are fixed:

| ID | Evaluated counts |
| --- | --- |
| input | `{}` |
| committed-pair | `{}` |
| source-layout | `{}` |
| candidate-layout | `{}` |
| source-inventory | `{documents,records,references,diagnostics}` |
| rewrite | `{files}` |
| candidate-preservation | `{changedPaths}` |
| candidate-ledger | `{allocations}` |
| candidate-structural | `{errors,warnings}` |
| candidate-values | `{checked,skipped,errors,hardErrors,warnings}` |
| temporary-disposal | `{}` |

Counters are nonnegative integers. A not-performed check or failure before its
counts are available has `{}`. changedPaths is computed from the complete actual
before/after tree maps even when preservation fails; unavailable comparisons
are not converted to an empty observed diff. Mechanical passed requires every
listed check passed. It may correspond to shim exit0, but impact is still not
performed and final policy is incomplete. Failed mechanical checks do not pass
merely because the report was well-formed or retained successfully.

## Input digest, runtime binding and disposal

The gate generates validationInputDigest with canonicalSha256 over exactly:

```js
{source, candidate, migrationInputs, limits,
 policy: {id:'identity-migration-publication-v1', version:1}}
```

There is no caller-supplied digest or runtime label. The executed runtime is
bound by P1's actual verified runtime manifest, exact raw gate report, and outer
report/bundle. No competing runtime probe or second input-hash preimage is
introduced. The gate digest retains none of its transient input values.

Private source/rewrite/correspondence-bearing references are discarded in
finally; shared materializers remove their temporary snapshots before completion.
Cleanup failure is a separate failed disposal check, never a successful gate.
Caller-owned inputs remain the caller's responsibility. This is disposal of
owned temporary data, not secure memory erasure.

Retained deliberate failures contain static codes/counters and ordinary source
paths, not replacement pairs, source identities joined to candidate identities,
raw adjudications, exception messages or a crosswalk. Runtime integration must
transport migrationInputs privately and retain no operation input.json. It may
retain the actual valid non-mapping report and its gate-generated digest; crashes,
malformed results or unexpected stderr require safe refusal and private cleanup.

The existing steward conversation/PR process reviews the exact candidate and
request. Recorded provenance relies on the trusted operator and review platform;
mechanical checks do not authenticate human attention. Candidate-ref retention
and governed store PR/merge adoption remain distinct operations.

## Preserved source roles for the first historical profile

Committed source inventory separately captures `preservedFiles` for the exact
three ordinary generated paths (`knowledge/derived/index.json`,
`tree.domain-form.md`, `tree.form-domain.md`) and the closed schema-1 empty rules
envelopes at `ontology/_rules.yaml` and `knowledge/_rules.yaml`. These files are
not passed to the identity rewriter. Whole-tree candidate preservation still
requires their original bytes and modes unchanged; semantic checks must generate
fresh detached outputs independently. Stale artifact bytes do not establish
preservation of generated behavior.

Nonempty rules, extra rule keys, wrong store/version, anchors/aliases/tags, and
unknown generated paths remain unclassified. The complete Subject directory is
also treated as unsupported source scope, rather than silently ignored because
the historical loader predates it. No source-format completeness follows merely
from a matching path.

The existing closed mechanical report is unchanged: `scope.sourceFiles` lists
all admitted identity-bearing and preserved files, and its document count and
maxSourceDocuments bound include both. Actual historical compatibility and the
retrieval, generated-view and operational-history surfaces still require the separate final migration execution.
That execution and its retained review/publication contract are implemented in
the [current finite final migration profile](ucs-1240-final-migration.md). This mechanical
gate continues reporting its own unchanged scope and unperformed impact.
