# Held-out agent comparison, 2026-09-24/25

The first agent evaluation with `ask`. Same six held-out cases, same reader
model, same content; only the runtime differs. Three repeats per case and
runtime, 36 sessions, the same shape as the earlier study. Per-session rows
are in [heldout-2026-09-24.json](heldout-2026-09-24.json).

## Result

| | Original runtime (08066b5) | Current runtime (rc.19) |
| --- | --- | --- |
| Sessions completed or correctly declined | 12 of 18 | 12 of 18 |
| Of the 12 sessions that ran | 12 of 12 | 12 of 12 |
| Blocked by the API before an answer | 6 | 6 |
| Sessions with a critical error | 0 | 0 |
| Reader cost, 18 sessions | $4.54 | $4.38 |
| Mean session time (sessions that ran) | 51 s | 47 s |

Paired by case and repeat: 12 ties, no regression, no improvement, and 6 pairs
blocked in both runtimes.

**Grading correction.** The first grading marked policy-01, current runtime,
repeat 3 as failed (`fabricated-citation`, `unsupported-claim`). A blind
diagnosis ([report](../../../docs/agents/2026-09-25-policy-01-miss-diagnosis.md))
found a grader error: the reader had both gold records at ranks 1 and 2 and
quoted them correctly, but the grader saw only file paths, and after
`migrate.js` a record keeps its 2.x file name while carrying a new ID. The
grader now sees what each tool returned (replayed for these recorded sessions:
the engine is deterministic and replayed output matched the recorded sizes),
and all 24 sessions that ran were regraded. That session is now `completed`;
no other verdict changed. The first grades stay in the rows as `verdictV1`.

In every session that ran, under both runtimes, engineering-01 and policy-01
were completed and cultural-research-01 and professional-services-01 were
correctly declined.

On the sessions that ran, the current runtime's reader made 10 to 22 tool calls
(the original's also 10 to 22) and received 49 to 63 KB of tool output across
the session (the original's 41 to 54 KB).

**Blocked sessions.** For manufacturing-01 and holding-company-01, the API
refused the reader session in all six sessions of each case, under both
runtimes, under its usage policy (a `[bio]` classifier tag); no answer was
produced. That is the model provider's classifier reacting to those cases'
content, not a runtime result. The sessions count as failures as the protocol
requires; they were not retried, replaced or rerouted to another model.

## Method

- **Cases.** Six new cases, one per development-v2 organization, three
  answerable and three scoped negatives. An independent custodian agent wrote
  them and a separate reviewer agent checked entailment and novelty against
  the 54 existing questions; 3 were accepted and 3 revised. They are sealed
  outside the repository; this repository holds only the
  [blinded receipt](../../../docs/agents/2026-09-24-heldout-custody-receipt.md).
  The engine's tuner never saw them. These are new cases: the result cannot be
  compared one to one with the earlier 15/18 vs 10/18 study, whose sealed cases
  no longer exist.
- **Content.** The eight development-v2 installations built as 2.x stores by
  the 08066b5 runtime (`materialize-corpus.js`), and the same stores converted
  by `migrate.js` into a fresh 3.0 kit (`arms.js`). Subjects are not part of
  either, so `ask` ran without Subject labels.
- **Readers.** One headless Claude Code session per case, runtime and repeat,
  Sonnet 5, isolated as described in the
  [retrieval README](../README.md#agent-evaluation), with a $2 budget per
  session. Model chosen on the public pilot tasks. Repeat 1 ran on 2026-09-24;
  repeats 2 and 3 on 2026-09-25 with the same model, budget and rubric.
- **Grading.** `grade.js` with Sonnet 5, rubric fixed before these sessions
  ran; regraded on 2026-09-25 with tool outputs visible (see above). Only
  verdict codes and critical flags left the custody directory.

## Limits

- Four usable cases, on which both runtimes answered every session correctly.
  The result shows no regression on these cases. It does not show that `ask`
  improves task completion: the cases were answerable with either runtime.
- All grades come from one grader model; case judgments come from one
  custodian and one reviewer, both agents.
- One case's key evidence partly overlaps records used by an existing
  development question (the reviewer could not avoid it in that organization).
- Two of six cases could not be measured at all with this reader model.
