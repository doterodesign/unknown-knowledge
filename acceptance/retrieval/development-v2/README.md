# Development-v2 reviewed source corpus

This draft expands the six frozen pilot organizations to eight development
tasks each: 42 new prompts and six carried prompts. All 48 have independent
source judgments against the expanded shared organization inventory. The three
reviewers derived expected responses from sources before seeing implementation
or runtime outputs, then applied the common `ADJUDICATION.md` rubric. Their
unchanged final JSON files and hashes are recorded in `source-review.json`.
After the five fixed clarification branches, 39 tasks are answerable and nine
lack a requested fact. These are source judgments, not execution results.

Record metadata, record-level grades, exact structural candidate sets and the
executable subject registry are still pending independent review. Do not use
this source-only corpus as a frozen executable comparison fixture.

`tasks.json` lists each organization's original and additional source files.
All its tasks share that complete source inventory. The original pilot sources
remain unchanged, including the excluded private decoy. Do not read that private
file in source review or trials. Holding-company sources describe three separate
namespaces; their records must not be merged into a fourth group installation.

Reviewers receive only the source files, task prompts and rubric. Derive expected
answers, evidence passages, decoys, scope restrictions, ambiguities, permissible
clarifications and abstentions from the source material before seeing any P10
judgments or runtime outputs. Flag inconsistent or underspecified source claims.
P10 reconciles review findings before authoring the graded record judgments and
separate exact structural candidate expectations.

The expanded policy source introduces a scoped VIP successor, so the original
policy question now needs to distinguish VIP tickets from ordinary tickets.
The engineering audit adds independent relevant evidence. These changes require
new judgments for the carried prompts; retaining their old denominator or
silently reusing the old expected answer would invalidate comparison.

All additional artifacts are invented, including studies, technical values,
policies, approvals and contacts. They have no operational authority outside
the fixture. Filenames and passages are source attribution, not new-runtime
identity aliases. `record-inventory.json` allocates 82 provisional canonical
source identities and passage attributions only. Kind/lifecycle/scope/subject
assignments must still be reviewed for fidelity before materialization; these
identities are not runtime aliases or a retained baseline/candidate crosswalk.

Numeric development-1 trial limits are agreed in `../DEVELOPMENT-BUDGETS.md`.
Exact host visibility/enforcement, dependency provenance and the actual target
runtime must be established before any paired or fresh-agent execution.
