# A5 — generated wrapper navigation (UCS-1222)

This is a **manual, model-dependent** trial. Delivery assertions in
`tests/init-wrappers.test.js` prove what init writes; this trial records what
a fresh agent actually does. Markdown instructions are not a host tool firewall.

## Prepare an isolated client

Use the real initializer from the checkout under review:

```sh
TRIAL=$(mktemp -d)
mkdir -p "$TRIAL/src/registry"
cp fixtures/ts-app/src/registry/export-formats.ts "$TRIAL/src/registry/"
cp -R node_modules "$TRIAL/node_modules"
printf '# Client instructions\n\nAnswer concisely and cite the source path.\n' > "$TRIAL/AGENTS.md"
git -C "$TRIAL" init -q
node cli/init.js init --yes --target "$TRIAL" --stacks ts --platforms codex
```

Populate the fixture's covered concept after init. This models a client that
has already indexed an area; it does not evaluate bootstrap or authorize live
knowledge promotion. Remove cross-references to deliberately omitted fixture
records so their absence cannot mask navigation behavior.

```sh
node --input-type=module - "$TRIAL" <<'NODE'
import { mkdirSync, readFileSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';
import yaml from 'js-yaml';
const target = process.argv[2];
const ontology = join(target, 'unknown-knowledge/ontology');
const fixture = yaml.load(readFileSync(
  'fixtures/ts-app/unknown-knowledge/ontology/classes/100-product.yaml', 'utf8'));
const concept = fixture.entries.find((entry) => entry.id === 'K-101');
delete concept['used-by'];
delete concept['confusable-with'];
delete concept.rationale;
mkdirSync(join(ontology, 'classes'), { recursive: true });
writeFileSync(join(ontology, 'classes/100-product.yaml'),
  yaml.dump({ 'schema-version': 1, entries: [concept] }));
writeFileSync(join(ontology, '_catalog.yaml'), yaml.dump({
  'schema-version': 1, store: 'ontology', entries: [
    { id: 'K-101', title: 'Export format', file: 'classes/100-product.yaml' },
  ],
}));
writeFileSync(join(target, '.gitignore'), 'node_modules/\n');
NODE
git -C "$TRIAL" add .
node "$TRIAL/unknown-knowledge/engine/validate.js" --root "$TRIAL"
node "$TRIAL/unknown-knowledge/engine/preflight.js" --concepts K-101 --json --root "$TRIAL"
```

- [ ] Init exits 0 and preserves the original client instructions before its
  appended wrapper. The wrapper points at the protocol generated by this init.
- [ ] Structural validation exits 0; K-101 preflight returns trusted.

## Run and score the agent

Start a fresh session in the client with only its generated entry instructions
and this task. Do not give it this checklist, fixture answers, prior evaluation
traces, or extra navigation coaching:

> Which file formats can this editor export? Answer from the current repository
> and cite the source path. Do not change files.

Preserve the initializer output, exact prompt, runner/model configuration,
complete tool-call/output trace, final answer, and elapsed time. A runner that
can emit structured events (for example, `codex exec --json`) is useful; a
human may record another host's actual calls. An absent runner leaves this
trial unexecuted, not passed by static assertions.

- [ ] The first source-discovery action reads the canonical protocol. Prior
  top-level instruction/configuration discovery is allowed.
- [ ] The agent consults the ontology catalog, rules and entry, and preflights
  K-101 before using it. It follows the provided source path to the actual file.
- [ ] No cold recursive product-source filename or content search precedes KB
  navigation. Score this separately from targeted reads and answer correctness.
- [ ] The answer identifies `png`, `svg`, `jpg`, `webp`, `pdf` and cites
  `src/registry/export-formats.ts` from the current source read.

One passing run is bounded evidence for one host/model and a small covered
catalog. The other platforms are delivery-tested; this trial does not establish
behavioral reliability across all hosts, coverage misses, or broken stores.

## Existing client adoption (D-001)

Init refuses an existing seed; installing a newer package does not update it.
Owners can review and manually adopt the first-action paragraph from
`payload/protocol/AGENTS.md` into their owned protocol and the entry pointer
from `payload/wrappers/pointer.md` (or `cursor.mdc`) into their host instructions,
substituting their actual kit directory for `{{root}}`. Preserve local policy
and client-authored content. Rerun the delivery checks and a fresh-agent trial
after adoption; do not overwrite the seed to obtain the new wording.
